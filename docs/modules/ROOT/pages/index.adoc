`smd.cl` is a compile-time Common Lisp compiler proof of concept targeting
C++26 on GCC16.  It demonstrates that a full language pipeline — from
source string to evaluated value — can be realised entirely within
constexpr and compile-time contexts.

== Pipeline

[source]
----
source string
  → reader (datum tree)
  → elaborator (core AST)
  → eval (small-step machine)
  → Beman Execution sender backend
----

== Quick Example

[source,cpp]
----
#include <smd/cl/conformance/driver.hpp>

// Run the expression (+ 1 2) through read -> elaborate -> eval.
// evaluate_program is constexpr, so this evaluates at compile time.
constexpr auto report = smd::cl::conformance::evaluate_program("(+ 1 2)");

static_assert(report.how.is_value());
// report.how.as_value() == smd::cl::eval::value{smd::cl::eval::value_fixnum{3}}
----

== Documented Modules

The API reference covers the non-reflection layers of the pipeline:

* *foundation* — `src/smd/kit/foundation`'s language-agnostic substrate
  (`static_vector`, `arena_box`, `result`, `functor`, `applicative`,
  `monad`) plus `src/smd/cl/foundation`'s front-end-specific additions
* *symbol* — the interned symbol table, `symbol_id`, `symbol_table`
* *reader* — datum types, `cursor`, `read_datum`
* *core* — the core AST types (`core_if`, `core_lambda`, `core_progn`, etc.)
* *elaborator* — `elaborate`, classifying datums into the core AST
* *eval* — the small-step `machine`, `outcome`, `value`, `environment`

The `sender` module uses Beman Execution and is documented separately from
the mrdocs-generated reference; reflection has not yet been ported to this
front end.
