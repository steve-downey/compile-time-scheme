`smd.schemepoc` is a compile-time Scheme-light compiler proof of concept
targeting C++26 on GCC16.  It demonstrates that a full language pipeline —
from source string to evaluated value — can be realised entirely within
constexpr and compile-time contexts.

== Pipeline

[source]
----
source string
  → reader (datum tree)
  → elaborator (core AST)
  → CPS / defunctionalized program
  → closure backend (constexpr evaluation)
  → Beman Execution sender backend
  → reflection reification spike
----

== Quick Example

[source,cpp]
----
#include <smd/smdscheme/smdscheme.hpp>

// Compile the expression (+ 1 2) at compile time.
// compiled_closure is a constexpr variable template.
constexpr auto &prog = smd::smdscheme::compiled_closure<"(+ 1 2)">;

// Evaluate at runtime with a default environment.
using Core = smd::smdscheme::closure::closure_program<32,16,...>::Core;
auto env   = smd::smdscheme::closure::default_env<Core, 16>();
auto result = prog(env);
// result.value() == 3
----

== Documented Modules

The API reference covers the non-reflection layers of the pipeline:

* *foundation* — `fix`, `arena_box`, `static_vector`, `result`,
  `functor`, `applicative`, `alternative` typeclass objects
* *parser* — combinatorial parser primitives (`cursor`, `parser`,
  `satisfy`, `alt`, `many`, `some`, `lift2`) and `parser_ops`
* *reader* — datum types, atom parsers, `read_datum`
* *elaborator* — core AST types (`core_if`, `core_lambda`, etc.) and `elaborate`
* *closure* — runtime values, `env`, closures, `eval_direct`,
  `compile_cps`, `closure_program`

The `sender` and `reflection` modules use GCC16-specific `*+-freflection+-*`
and are not yet covered by the generated API reference.
